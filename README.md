# user-management-service

Микросервис для управления пользователями с аутентификацией на основе JWT-токенов.

## О проекте

Сервис представляет собой backend-приложение, построенное на микросервисной архитектуре. Он отвечает за регистрацию, аутентификацию и управление профилем пользователя.
Архитектура

Проект состоит из нескольких микросервисов, взаимодействующих через gRPC и HTTP:
* API Gateway - единая точка входа для клиентов, обрабатывает HTTP-запросы и маршрутизирует их к соответствующим сервисам
* Auth Service - отвечает за аутентификациюm, авторизацию и управление JWT-токенами
* User Service -  управляет профелем пользователей (создание, обновление логина, получение user_id профеля, удаление)

**Основные цели проекта:**
*   Изучить принципы построения микросервисной архитектуры.
*   Научиться использовать gRPC и Protobuf для межсервисного взаимодействия.
*   Реализовать безопасную аутентификацию с помощью JWT.
## Стек технологий
*   **Язык:** Golang
*   **Фреймворки/Библиотеки:** Gin, Gorm, Testify
*   **Коммуникация:** gRPC, Protobuf
*   **Базы данных:** PostgreSQL (основные данные), MongoDB (доп. данные), Redis (кеш/сессии)
*   **Аутентификация:** JWT
*   **Документация:** Swagger
*   **Инфраструктура:** Docker, Docker Compose
*   **Миграции:** собственные или с использованием Gorm
*   **Тестирование:** Unit-тесты, интеграционные тесты

## Установка и запуск

### Предварительные условия

1.  Установленный [Docker](https://www.docker.com/) и Docker Compose.
2.  (Опционально) Установленный Go для локальной разработки.

### Запуск через Docker Compose (рекомендуется)

1.  Клонируйте репозиторий:
    ```bash
    git clone https://github.com/mmrgreenteaa/user-management-service.git
    cd user-management-service
    ```

2.  Запустите все сервисы:
    ```bash
    docker-compose up --build
    ```

    *Приложение будет доступно по адресу `http://localhost:8080` (или по другому порту, указанному в конфигурации).*

    **Важно:** Сервис аутентификации (`auth`) может потребовать дополнительное время для инициализации. Если он не запустился автоматически, проверьте логи и при необходимости запустите его контейнер отдельно.


## Использование API

После запуска сервиса:
*   **REST API** будет доступно по адресу `http://localhost:8080/api/v1`.
*   **Документация Swagger** будет доступна по адресу `http://localhost:8080/swagger/index.html`.
*   **gRPC**-сервисы будут слушать указанные в конфигурации порты.
